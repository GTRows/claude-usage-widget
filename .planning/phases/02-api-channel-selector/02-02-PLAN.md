<objective>
Surface the channel selector and the Anthropic API key input in the settings drawer, wire IPC for the encrypted key, and round-trip both through `electron-store`. After this plan the user can switch between `webSession` and `apiKey` from the UI, paste an API key into a masked input, and have the dispatcher pick the right channel at the next window expiry without restarting the app.

Purpose: Plan 02-01 left the API channel reachable only by hand-editing the config file. This plan exposes it in the GUI with localized strings and the same drawer styling already used for the existing toggles. The schema enum (`src/shared/settings-schema.js` line 35: `autoFireChannel: ['webSession', 'apiKey']`) is already in place from plan 01-03, so no schema migration is needed.

Output: a channel selector control + masked API-key input row in `src/renderer/index.html`, hydration/save wiring in `src/renderer/app.js`, two new IPC channels (`save-api-key` and `clear-api-key`) bridged through `preload.js`, and localized strings (en + tr) added to the existing inline `_AUTO_FIRE_STRINGS` table at the top of `src/renderer/app.js` (lines 3–23). No new runtime dependency, no protected-file edits.
</objective>

  <name>Task 4: Add IPC for save/clear/has API key</name>
  <files>main.js, preload.js</files>
  <action>
Two surgical additions, one in each file.

Edit 1 — `main.js`:

Add three new IPC handlers near the existing `'save-credentials'` / `'logout'` handlers (around lines 371–391). Reuse the `readStoredApiKey` / `writeStoredApiKey` helpers added in plan 02-01 Task 3.

```js
ipcMain.handle('save-api-key', (event, apiKey) => {
  if (typeof apiKey !== 'string' || apiKey.length === 0) {
    return { ok: false, reason: 'empty' };
  }
  writeStoredApiKey(apiKey);
  return { ok: true };
});

ipcMain.handle('clear-api-key', () => {
  writeStoredApiKey('');
  return { ok: true };
});

ipcMain.handle('has-api-key', () => {
  return readStoredApiKey() !== null;
});
```

Notes:
- `save-api-key` accepts the raw string via IPC. Electron's contextBridge serializes safely; the key is never persisted to disk in plain text when `safeStorage.isEncryptionAvailable()` is true (the helper from plan 02-01 enforces that).
- `has-api-key` returns a plain boolean, not the key itself. The renderer never reads the key — it only writes it and asks whether one exists.
- No legacy plain-key path is exposed via IPC. The fallback to plain-text storage when keychain is unavailable is internal to `writeStoredApiKey`; the renderer cannot bypass it.
