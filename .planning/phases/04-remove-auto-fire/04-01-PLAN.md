<objective>
Hard-remove the auto-fire 5-hour-window-renewal feature shipped in v1.14.0-gtrows.1. The feature is functionally a no-op (placeholder payload that never actually starts a real Claude.ai 5-hour window) and we have decided to drop it rather than research the billable claude.ai endpoint. After this plan: zero references to `auto-fire`, `autoFire`, `apiKey` (the Anthropic API key — not to be confused with the unrelated `safeStorage`-encrypted `sessionKey`), `_AUTO_FIRE_STRINGS`, `_autoFireT`, `_applyAutoFireStrings`, or `_applyAutoFireRowVisibility` exist anywhere under `main.js`, `preload.js`, `src/`, or `tests/`. Four module files under `src/main/auto-fire/` and four spec files under `tests/auto-fire-*.test.js` are deleted from disk. The schema keys `autoFireEnabled` and `autoFireChannel` are removed from `src/shared/settings-schema.js` and `tests/settings-schema.test.js`; any persisted store entry for those keys is silently dropped on next save by virtue of `normalizeSettings` only iterating `SETTINGS_DEFAULTS` keys. The encrypted Anthropic API key persisted under `apiKey_encrypted` / `apiKey` in electron-store is deleted on first boot of the new build via a tiny one-shot store cleanup so the secret does not linger in user profiles.

Purpose: Ship v1.15 without the user-visible no-op. The roadmap (`.planning/ROADMAP.md` Phase 4) and `STATE.md` (Phase 4 pivot 2026-05-08, blocker entry) both call this out as the gating fix before v1.15 user-facing work (drag fix, manual update check, full tr/en localization). This plan executes that decision in one atomic sweep so subsequent phases (5-7) work on a clean tree.

Output:
- Edits to `main.js` (delete 4 requires, scheduler instance + `expired` listener, `getCredentialsForAutoFire`, `readStoredApiKey`, `writeStoredApiKey`, the dispatcher instance + `start()` call, the `save-api-key` / `clear-api-key` / `has-api-key` IPC handlers, the `writeStoredApiKey('')` line inside the `delete-credentials` handler, the scheduler `arm`/`disarm` block in `fetch-usage-data`, and the dispatcher/scheduler shutdown in `before-quit`; add a one-shot `store.delete('apiKey')` + `store.delete('apiKey_encrypted')` cleanup at boot).
- Edits to `preload.js` (delete the `saveApiKey`, `clearApiKey`, `hasApiKey` bridges and their group comment).
- Edits to `src/shared/settings-schema.js` (delete `autoFireEnabled` + `autoFireChannel` from `SETTINGS_DEFAULTS` and `autoFireChannel` from `ENUM_VALUES`).
- Edits to `tests/settings-schema.test.js` (delete the three `autoFire*` cases).
- Edits to `src/renderer/index.html` (delete the three `<div class="settings-item">` blocks for `autoFire`, `autoFireChannel`, `autoFireApiKey`).
- Edits to `src/renderer/app.js` (delete `_AUTO_FIRE_STRINGS`, `_autoFireT`, `_applyAutoFireStrings`, `_applyAutoFireRowVisibility`; the elements-cache entries; the `_applyAutoFireStrings()` call in init; the channel-select / save / clear listeners; the `loadSettings` hydration block; the `autoFireEnabled` + `autoFireChannel` save path).
- Edits to `src/renderer/styles.css` (delete the three `.auto-fire-api-key-*` rule blocks).
- Deletions of `src/main/auto-fire/{scheduler,dispatcher,web-channel,api-channel}.js` and `tests/auto-fire-{scheduler,dispatcher,web-channel,api-channel}.test.js` plus the now-empty `src/main/auto-fire/` directory.
- No new files, no new dependencies, no protected files modified (the require list change in `main.js` is content-only; `package.json` is not touched).
</objective>
