Decisions recorded in this plan:
- **Translation scope: every user-facing string, including notification copy, dialog titles, and the CLI HELP block** — not renderer-only. Reasoning: the user explicitly noted "tray menus, dialog text" and "CLI (bin/cli.js)" in scope, and `CLAUDE.md` requires `User-facing strings must NOT be hard-coded`. The CLI's `claude-usage --help` is a user-facing surface; users expect it to honor the same locale they picked in the widget.
- **Attribute-translation pattern: `data-i18n` for text nodes plus `data-i18n-attr="title:key,placeholder:key"` for attributes** — not a full templating engine, not separate `data-i18n-title` / `data-i18n-placeholder` per attribute. Reasoning: (1) the renderer is plain `<script>`-loaded; introducing a templating engine forces a build step. (2) Per-attribute attributes create a markup-pattern explosion as new attributes are added; one comma-separated attribute keeps a single seam. (3) The format `attr:key` parses with a single `String.split(',')` plus `String.split(':')` — no regex, no library.
- **Initial-text fallback: keep the English literal as the static text** — not a `data-i18n-default` attribute. Reasoning: if `i18n-renderer-shim.js` ever fails to load (CSP block, file-system race), the user still sees English text. With a default attribute they would see the key string. This matches the project's existing defensive pattern for error states.
- **Reactive re-render on `language-changed`: re-walk the DOM, do NOT rebuild it** — not React-style diffing, not `document.replaceChild`. Reasoning: `applyTranslations()` traversing `[data-i18n]` and `[data-i18n-attr]` is O(N) over translatable nodes (~150 in this app), runs in a few ms, and preserves event listeners and form state (the user's typed-in `sessionKeyInput`, the selected `historyPageSize`, the open/closed state of the settings drawer). A full DOM rebuild would lose all of that. Dynamic strings rendered in `app.js` (e.g. `Math.round(percentage)%`) are NOT in the DOM walk; they re-render on the next state-update tick (the existing `requestAnimationFrame` cycle that already fires every poll).
- **Plural handling for `samples` / `sample` (the only count-aware strings, at `app.js:1990` and `app.js:2440`): two flat keys** — not a full ICU `{count, plural, ...}` pipeline. Reasoning: per 07-01's research finding ("if a count-aware string actually appears, 07-02 can handle with two flat keys"). Introduce `history.samplesOne` and `history.samplesOther` plus a tiny inline ternary `samples === 1 ? t('history.samplesOne', { n }) : t('history.samplesOther', { n })`. Turkish has no plural inflection on countables (`1 örnek` / `5 örnek`), so the Turkish dictionary maps both keys to the same value. Forward-compatible with ICU plurals later.
- **Notification title becomes a translatable key — but the value stays `'Claude Widget (GTRows)'` in both locales** — not `'Claude Widget'` translated to Turkish. Reasoning: that string is the product name (matches `IDENTITY.yaml#identity.display_name`), not a translatable phrase. Routing it through `t('app.productName')` keeps every user-visible string discoverable in the locale files (so a future translator KNOWS the brand name is intentionally not translated). Same pattern as the `'CSV'` / `'JSON'` button labels.
- **Renderer boot order: shim loads dictionaries -> renderer reads `settings.language` from main IPC -> renderer calls `window.i18n.setLanguage(lang)` -> renderer calls `applyTranslations()` once on first paint** — not "renderer renders English first, then re-renders Turkish on next tick". Reasoning: the page would visibly flash English then snap to Turkish on Turkish-default machines. Doing the language pull synchronously inside `loadSettings()` (already on the boot critical path) and BEFORE the first `applyTranslations()` keeps the first-paint string in the right language. The shim's `module.exports` plus `window.__locales` dual-export from 07-01 already loads both dictionaries synchronously on `<script>` parse, so `t()` is callable the moment the script tag executes.
- **CLI boot order: read `settings.language` from widget store -> `setLanguage(...)` -> first `t()` call** — not "CLI defaults to `tr`, lets users override with `--lang en`". Reasoning: a `--lang` flag is feature creep; the user picked a language in the widget and expects the CLI to honor that single source of truth. If the widget store does not exist (CLI-only user, never opened the widget), fall back to `'tr'` (the project default per `CLAUDE.md`). 07-03 may revisit if a CLI-only flag is ever needed.

import { describe, it, expect } from 'vitest';
import { createRequire } from 'node:module';

const KEY_REGEX = /(?:^|[^\w])(?:i18n\.t|window\.i18n\.t|\bt)\(['"]([\w.]+)['"]/g;

function extractKeysFromFile(relPath) {
  const abs = join(__dirname, relPath);
  const src = readFileSync(abs, 'utf8');
  const keys = new Set();
  let match;
  while ((match = KEY_REGEX.exec(src)) !== null) {
    keys.add(match[1]);
  }
  return keys;
}

describe('i18n key catalog', () => {
  it('both locales have identical key sets', () => {
    const trKeys = Object.keys(tr).sort();
    const enKeys = Object.keys(en).sort();
    expect(trKeys).toEqual(enKeys);

    expect(en['common.loading']).toBeTruthy();
    expect(en['common.dismiss']).toBeTruthy();
  });

  it('every t(...) call site references a key that exists in both locales', () => {
    const allUsedKeys = new Set();
    for (const file of SOURCE_FILES) {
      for (const k of extractKeysFromFile(file)) allUsedKeys.add(k);
    }
    const missing = [];
    for (const key of allUsedKeys) {
      if (!Object.prototype.hasOwnProperty.call(tr, key)) missing.push(`tr:${key}`);
      if (!Object.prototype.hasOwnProperty.call(en, key)) missing.push(`en:${key}`);
    }
    expect(missing).toEqual([]);
  });

  it('every locale value is a non-empty string', () => {
    for (const [k, v] of Object.entries(tr)) {
      expect(typeof v, `tr.${k}`).toBe('string');
      expect(v.length, `tr.${k}`).toBeGreaterThan(0);
    }
    for (const [k, v] of Object.entries(en)) {
      expect(typeof v, `en.${k}`).toBe('string');
      expect(v.length, `en.${k}`).toBeGreaterThan(0);
    }
  });

  it('every key avoids ${name} and %s placeholders (only {name} allowed)', () => {
    for (const [k, v] of Object.entries(tr)) {
      expect(v.includes('${'), `tr.${k} contains template-literal syntax`).toBe(false);
      expect(v.match(/%[sd]/), `tr.${k} contains printf-style placeholder`).toBeNull();

    for (const [k, v] of Object.entries(en)) {
