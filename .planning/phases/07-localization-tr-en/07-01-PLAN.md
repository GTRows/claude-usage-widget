<objective>
Stand up the i18n foundation that plans 07-02 (string migration) and 07-03 (Language selector + UAT) will build on. Today the codebase has zero localization seam: every UI string in `src/renderer/index.html`, `src/renderer/app.js`, the tray menu in `main.js` (`'Show Widget'`, `'Refresh'`, `'Log Out'`, `'Exit'`, `setToolTip('Claude Widget (GTRows)')`), the `setToolTip` calls at `main.js:225/934/945`, the inline literals introduced by Phase 6 (`'Check now'`, `'Checking…'`, `'Up to date.'`, `'Check failed — try again.'`, `'Version X available — click the banner to download.'`, `'Last checked: <date> <time>'`, `'Not checked yet.'`), and every label in the CLI render layer is an English literal. There is also no `language` key in `src/shared/settings-schema.js#SETTINGS_DEFAULTS`, no enum entry in `ENUM_VALUES`, no IPC pipe for language, no preload bridge, and no electron-store path. The deferred-issues log (`.planning/ISSUES.md`) records that the i18n library decision was moved into this phase and that plan 07-01 owns it.

After this plan: a single shared module `src/shared/i18n.js` exposes `t(key, vars?)`, `setLanguage(lang)`, `getLanguage()`, and `getLocaleTag()`. Two locale source files live under `src/shared/locales/{tr,en}.js` as plain CommonJS objects, dot-keyed, with `{name}`-style placeholder interpolation. The `language` setting is added to `SETTINGS_DEFAULTS` (default `'tr'`) and `ENUM_VALUES.language = ['tr', 'en']`, the `get-settings`/`save-settings` IPC handlers in `main.js` round-trip it through `electron-store` like every other key, the main process applies the language by calling `setLanguage(...)` on app boot before the tray menu is built (so when 07-02 migrates the four tray labels they render in the correct language from the first paint), the renderer applies it via the same shared module so 07-02 can wrap strings without touching this skeleton, and the CLI loads the same module so 07-02 can localize CLI output too. A vitest spec under `tests/i18n.test.js` covers the four behaviours: load both locales without throwing, fall back to `en` when a key is missing in the active locale and to the key string when missing in both, interpolate `{var}` placeholders, and refuse to set an unknown language. No string migration in this plan — every existing English literal stays put. No Language selector UI in this plan (07-03 owns the drawer row + UAT).

Decision recorded in this plan (research finding):
- **Library: home-grown `t()`** — not `i18next`, not `format-js`, not `lingui`. Reasoning: (1) `CLAUDE.md` rules state "Adding a new dependency requires explicit discussion" and "the project deliberately keeps its dependency surface tiny (chart.js + electron-store only at runtime)". (2) The translatable surface is two languages (tr, en) with no plural rules deeper than `count === 1` and no RTL or BiDi requirements. (3) i18next is ~50KB minified and pulls a chain of plugins for the simplest features; format-js (FormatJS / react-intl) is React-coupled. Both are overkill for a vanilla-JS widget with two locales. (4) The home-grown shape can be re-implemented inside i18next later (the `t(key, vars)` signature is intentionally i18next-compatible) if a third language or ICU plurals are ever required, so this is not a one-way door.
- **Source format: plain JS objects (CommonJS)** — not JSON, not gettext `.po`, not ICU. Reasoning: (1) main and CLI are CommonJS — `require('./locales/tr')` is zero-friction; (2) JSON would force a `JSON.parse(fs.readFileSync(...))` boot step in main and a `fetch('./locales/tr.json')` step in the renderer (the renderer is `<script>`-loaded, no module bundler), both of which we avoid by using a CommonJS object that the renderer can also `require`-equivalent-load via a small inline `<script src="...">` pattern; (3) gettext's PO-file tooling requires a build step — there is no bundler; (4) ICU plurals are unused. Dot-keyed flat objects (`{ "settings.title": "Settings", "settings.language.label": "Dil" }`) keep diff hygiene clean and let 07-02 migrate strings file-by-file without restructuring.
- **Reach: main + renderer + CLI** — not renderer-only. Reasoning: tray menu labels (`Show Widget` / `Refresh` / `Log Out` / `Exit`) live in main; the CLI exposes user-facing labels via `src/cli/render.js`. Putting the seam in `src/shared/` (which is already CommonJS, dependency-free, and consumable by all three layers per `STRUCTURE.md` line 95-98) means 07-02 has one helper to import everywhere.
- **Placeholder syntax: `{name}`** — not `%s`, not `${name}`, not ICU `{name, plural, ...}`. Reasoning: `{name}` is unambiguous in JSON-style values, free of conflict with template-literal back-ticks already used heavily in `app.js`, and trivial to migrate to ICU later if needed. No nesting, no formatters, no plural categories in this skeleton — 07-02 can introduce a `tn(key, count, vars)` if a count-aware string actually appears (so far the only candidate is `samples === 1 ? 'sample' : 'samples'` at `app.js:2440`, which 07-02 can handle with two flat keys).
- **Default language: `tr`** — per `CLAUDE.md` "Default / fallback: tr". The fallback chain when a key is missing: `active locale -> 'en' -> the literal key string`. English is the last-resort source of truth for keys 07-02 forgets to translate, matching the existing English-literal surface.
- **Renderer language detection on first run: respect the persisted `settings.language` only.** No `navigator.language` heuristic, no system-locale detection. The default is hard-coded `'tr'` per `CLAUDE.md`. Users who want English flip the Language selector that 07-03 ships. (`navigator.language` was used in the now-deleted `_AUTO_FIRE_STRINGS` seam from Phase 1; that approach is explicitly rejected here because it produced surprise behaviour on Turkish machines that wanted the English UI.)

```js
const en = require('./locales/en');
const tr = require('./locales/tr');

const SUPPORTED_LANGUAGES = ['tr', 'en'];
const DEFAULT_LANGUAGE = 'tr';
const FALLBACK_LANGUAGE = 'en';

const dictionaries = { tr, en };

let activeLanguage = DEFAULT_LANGUAGE;

function setLanguage(lang) {
  if (!SUPPORTED_LANGUAGES.includes(lang)) return false;
  activeLanguage = lang;
  return true;
}

function getLanguage() {
  return activeLanguage;
}

function getLocaleTag() {
  // BCP-47 tag for callers that need Intl.DateTimeFormat / Intl.NumberFormat.
  return activeLanguage === 'tr' ? 'tr-TR' : 'en-US';
}

function interpolate(template, vars) {
  if (!vars) return template;
  return template.replace(/\{(\w+)\}/g, (match, name) => {
    if (Object.prototype.hasOwnProperty.call(vars, name)) {
      return String(vars[name]);
    }
    return match;
  });
}

function t(key, vars) {
  if (typeof key !== 'string' || !key) return '';
  const active = dictionaries[activeLanguage];
  if (active && Object.prototype.hasOwnProperty.call(active, key)) {
    return interpolate(active[key], vars);
  }
  const fallback = dictionaries[FALLBACK_LANGUAGE];
  if (fallback && Object.prototype.hasOwnProperty.call(fallback, key)) {
    return interpolate(fallback[key], vars);
  }
  return key;
}

module.exports = {
  t,
  setLanguage,
  getLanguage,
  getLocaleTag,
  SUPPORTED_LANGUAGES,
  DEFAULT_LANGUAGE
};
```

import { describe, it, expect, beforeEach } from 'vitest';
import { createRequire } from 'node:module';

const requireCJS = createRequire(import.meta.url);
const I18N_PATH = requireCJS.resolve('../src/shared/i18n.js');
const TR_PATH = requireCJS.resolve('../src/shared/locales/tr.js');
const EN_PATH = requireCJS.resolve('../src/shared/locales/en.js');

function freshI18n() {
  delete requireCJS.cache[I18N_PATH];
  delete requireCJS.cache[TR_PATH];
  delete requireCJS.cache[EN_PATH];
  return requireCJS(I18N_PATH);
}

describe('i18n shared module', () => {
  let i18n;

  beforeEach(() => {
    i18n = freshI18n();
  });

  it('loads both locales at boot and defaults to tr', () => {
    expect(i18n.SUPPORTED_LANGUAGES).toEqual(['tr', 'en']);
    expect(i18n.DEFAULT_LANGUAGE).toBe('tr');
    expect(i18n.getLanguage()).toBe('tr');
    expect(i18n.t('common.loading')).toBe('Yükleniyor…');
  });

  it('switches language and reflects it in t() and getLocaleTag()', () => {
    expect(i18n.setLanguage('en')).toBe(true);
    expect(i18n.getLanguage()).toBe('en');
    expect(i18n.t('common.loading')).toBe('Loading…');
    expect(i18n.getLocaleTag()).toBe('en-US');

  it('falls back from active locale to en, and from en to the key string', () => {
    // tr is active; pretend a key is missing in tr but present in en by deleting it post-load.
    // Simpler: query a key only present in en (we know none of the seed keys are en-only).
    // Instead, validate the literal-key fallback for a key that exists in neither.
    expect(i18n.t('definitely.not.a.real.key')).toBe('definitely.not.a.real.key');
    // And the en-fallback path: temporarily mutate the active dict in memory.
    const tr = requireCJS(TR_PATH);
    delete tr['common.dismiss'];
    expect(i18n.t('common.dismiss')).toBe('Dismiss'); // falls through to en
  });

  it('interpolates {var} placeholders', () => {
    // Inject a templated key into both locales for the test scope.
    const tr = requireCJS(TR_PATH);
    const en = requireCJS(EN_PATH);
    tr['test.greet'] = 'Merhaba {name}!';

    expect(i18n.t('test.greet', { name: 'Ada' })).toBe('Hello Ada!');
    // Unknown placeholder stays as-is.
    expect(i18n.t('test.greet', { wrong: 'x' })).toBe('Hello {name}!');

  it('refuses unknown languages and leaves state unchanged', () => {
    expect(i18n.setLanguage('en')).toBe(true);
    expect(i18n.setLanguage('xx')).toBe(false);
    expect(i18n.getLanguage()).toBe('en'); // not reverted, not corrupted

  it('returns empty string for non-string keys without throwing', () => {
    expect(i18n.t()).toBe('');
    expect(i18n.t(null)).toBe('');
    expect(i18n.t('')).toBe('');
  });
});

(function () {
  if (typeof window === 'undefined') return;
  const locales = (window.__locales = window.__locales || {});

  const SUPPORTED = ['tr', 'en'];
  const DEFAULT_LANG = 'tr';
  const FALLBACK_LANG = 'en';

  let active = DEFAULT_LANG;

  function setLanguage(lang) {
    if (!SUPPORTED.includes(lang)) return false;
    active = lang;
    return true;
  }

  function getLanguage() {
    return active;
  }

  function getLocaleTag() {
    return active === 'tr' ? 'tr-TR' : 'en-US';
  }

  function interpolate(template, vars) {
    if (!vars) return template;
    return template.replace(/\{(\w+)\}/g, (m, name) => (
      Object.prototype.hasOwnProperty.call(vars, name) ? String(vars[name]) : m
    ));
  }

  function t(key, vars) {
    if (typeof key !== 'string' || !key) return '';
    const a = locales[active];
    if (a && Object.prototype.hasOwnProperty.call(a, key)) return interpolate(a[key], vars);
    const f = locales[FALLBACK_LANG];
    if (f && Object.prototype.hasOwnProperty.call(f, key)) return interpolate(f[key], vars);
    return key;
  }

  window.i18n = {
    t,
    setLanguage,
    getLanguage,
    getLocaleTag,
    SUPPORTED_LANGUAGES: SUPPORTED,
    DEFAULT_LANGUAGE: DEFAULT_LANG
  };
})();
