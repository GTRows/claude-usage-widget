<objective>
Build the window-expiry detector and background scheduler in the Electron main process. The scheduler observes the active 5-hour Claude usage window's `resets_at` timestamp (already exposed by the existing usage poll) and fires a single "auto-fire trigger" event the moment that timestamp passes. The trigger is emitted as an internal Node `EventEmitter` event consumed by the channel module added in plan 01-02 — no network call happens in this plan.

Purpose: Provide a single, race-free, app-lifetime "window expired" signal so plan 01-02 can hook a payload-sender to it without re-implementing scheduling. This isolates timing logic from request logic so each can be tested independently.

Output: A new module `src/main/auto-fire/scheduler.js` plus minimal wiring in `main.js`. No renderer / IPC / settings work in this plan (those land in 01-03). No Claude.ai HTTP request in this plan (lands in 01-02).
</objective>

<task type="auto">
  <name>Task 1: Create the auto-fire scheduler module</name>
  <files>src/main/auto-fire/scheduler.js</files>
  <action>
Create a new CommonJS module that exports a small class / factory `createAutoFireScheduler({ now = Date.now, setTimeout: setT = setTimeout, clearTimeout: clearT = clearTimeout } = {})`. Inject the timer + clock so tests can drive it deterministically (vitest pattern already used in `tests/cli-config.test.js`).

The scheduler owns one mutable piece of state — the next-armed expiry timestamp — and exposes:

- `arm(resetsAtIso)` — schedule a single fire for `Date.parse(resetsAtIso) + JITTER_MS` from `now()`. If the timestamp is in the past or within `MIN_DELAY_MS` (5 seconds), fire immediately on `process.nextTick` so the event still passes through the EventEmitter on a clean stack. If a timer is already armed for the same epoch ms (within 1s), do nothing — idempotent so the usage poll calling `arm()` every refresh does not stack timers.
- `disarm()` — clear any pending timer and forget the armed timestamp.
- `getArmedAt()` — return the currently armed epoch ms or `null`. Used by tests + debug log.
- `on('expired', listener)` / `off('expired', listener)` — proxy `EventEmitter` so the module is composable. The `'expired'` event fires with the armed `resetsAtIso` string and the actual fire-time epoch ms: `emitter.emit('expired', { resetsAtIso, firedAt: now() })`.

Constants at top of file: `MIN_DELAY_MS = 5_000`, `JITTER_MS = 2_000` (small fixed delay after the boundary so we are unambiguously past it; do not randomise — determinism matters for tests). Module is ~80–120 lines, well under the 200-line cap.

Use `require('events')` for the EventEmitter. CommonJS exports: `module.exports = { createAutoFireScheduler, MIN_DELAY_MS, JITTER_MS };`. Style: 2-space indent, single quotes, semicolons, no JSDoc on this fresh code beyond a short top-of-file comment explaining WHY (the ordering rule: arm-before-fire, idempotent re-arm). No `console.log`; keep the module pure / Electron-free so tests run in plain Node.
  </action>
  <verify>
Run `node -e "const { createAutoFireScheduler } = require('./src/main/auto-fire/scheduler'); const s = createAutoFireScheduler(); s.on('expired', (p) => console.log('fired', p)); s.arm(new Date(Date.now()+50).toISOString());"` and confirm `fired { resetsAtIso: '...', firedAt: <number> }` is printed within ~2.1s.
  </verify>
  <done>Module file exists, exports `createAutoFireScheduler`, `MIN_DELAY_MS`, `JITTER_MS`. Manual smoke command above prints one `fired` line. No emojis, no TODOs, no console.log left in the module.</done>
</task>

<task type="auto">
  <name>Task 2: Add deterministic unit tests for the scheduler</name>
  <files>tests/auto-fire-scheduler.test.js</files>
  <action>
New vitest spec covering the scheduler in pure Node. Mirror existing test style (see `tests/peak-throttle.test.js` and `tests/version.test.js`): ESM `import`, `createRequire(import.meta.url)` to load the CommonJS module, `beforeEach`/`afterEach` to reset state. Drive time with `vi.useFakeTimers()` + `vi.setSystemTime()`; do not use real timers.

Cases (one `it` each):
1. `arm()` fires `'expired'` exactly once when fake-time advances past `resetsAt + JITTER_MS`.
2. `arm()` with a timestamp already in the past fires on `process.nextTick` (use `await Promise.resolve()` then advance microtasks; assert listener called once with the original ISO string).
3. Re-arming with the same `resetsAtIso` while a timer is still pending does NOT stack timers (assert only one fire after advancing past the boundary).
4. Re-arming with a LATER `resetsAtIso` cancels the prior timer and fires only once at the new boundary (advance to old boundary: zero fires; advance to new boundary: one fire).
5. `disarm()` after `arm()` produces zero fires when fake-time advances past the boundary.
6. `getArmedAt()` returns `null` initially, the armed epoch ms after `arm()`, and `null` after `disarm()` or after firing.
7. The injected `setTimeout` / `clearTimeout` are used (assert via `vi.fn()` spies) — proves the seam works.

Pattern from existing specs:
```js
import { describe, it, expect, beforeEach, afterEach, vi } from 'vitest';
import { createRequire } from 'module';
const require = createRequire(import.meta.url);
let mod;
beforeEach(() => {
  vi.useFakeTimers();
  delete require.cache[require.resolve('../src/main/auto-fire/scheduler')];
  mod = require('../src/main/auto-fire/scheduler');
});
afterEach(() => { vi.useRealTimers(); });
```

<task type="auto">
  <name>Task 3: Wire the scheduler into main.js after every usage fetch</name>
  <files>main.js</files>
  <action>
At the top of `main.js` add `const { createAutoFireScheduler } = require('./src/main/auto-fire/scheduler');` next to the other local requires (after `peakThrottleShared`).

Create one module-scoped instance: `const autoFireScheduler = createAutoFireScheduler();`. Place it next to other module singletons (near `let mainWindow = null;`). Do NOT export it from main.js — plan 01-02 will pass it (or its event emitter) to the channel module via a function call, not a global.

Inside the existing `ipcMain.handle('fetch-usage-data', ...)` handler in `main.js` (currently around lines 809–919), AFTER the line `storeUsageHistory(data);` and BEFORE the always-on-top reassertion block, add:

```js
const fiveHourResetsAt = data?.five_hour?.resets_at;
if (fiveHourResetsAt) {
  autoFireScheduler.arm(fiveHourResetsAt);
} else {
  autoFireScheduler.disarm();
}
```

Reason for placement: the usage poll is the single source of truth for `resets_at` (see `ARCHITECTURE.md` Flow 1, step 5 already mutates `data` here). Calling `arm()` every successful fetch is safe because the scheduler is idempotent for the same timestamp.

Also add a single debug log: when the scheduler emits `'expired'`, call `debugLog('[AutoFire] window expired', payload.resetsAtIso, 'fired at', new Date(payload.firedAt).toISOString());`. Wire this once at app start, near where `defaultTrayImage` etc. are initialised — but do NOT do it inside `app.on('ready', ...)` (the listener should be installed before ready so a very early fetch is not missed). Subscribe with `autoFireScheduler.on('expired', (payload) => { debugLog(...); });`. No other behaviour wired in this plan — plan 01-02 will add the request firing.

Do NOT touch the renderer, preload, or settings schema in this plan.
Do NOT add any new IPC channel.
Do NOT introduce new dependencies.
